New app runbook

The source-of-truth workflow for Partner data, GA4, and Shopify listing attribution.

Steps1. Create draft2. Partner API3. GA44. Shopify listing5. Activate6. Verify7. Rotate secrets

1. Create the draft

Create the Partner organization first if it is new, then add the app in App management. Keep its status Draft until all checks below pass. Use the real primary listing locale; do not assume English.

2. Partner API

Create or locate the Partner API client for the organization. Put the token in Dokku under the ENV name stored on the organization.

dokku config:set mantle SHOPIFY_PARTNER_TOKEN_ORGID='<partner-token>'

Success signal: Integrations shows Token present. Never paste the token into this form, Git, logs, screenshots, or documentation.

3. GA4 property and stream

  1. Create one GA4 property and web stream for the app listing.
  2. Grant the shared Mantle service account Viewer access.
  3. Record the numeric property ID and the shared credentials ENV name.
  4. In the web stream, acknowledge the user-data collection terms and create one Measurement Protocol API secret.

Success signal: the app shows a property ID and Credentials present.

4. Connect the Shopify listing

Open the listing editor for its actual primary locale and enter the GA4 Measurement ID and API secret. If Shopify shows Submitted or In review, those fields can be locked: record that listing status, set tracking to Blocked, and explain it in the status note. Finish after review approval.

5. Activate

Set listing and tracking states explicitly, enter every full annual charge amount, then change the app to Active. Activation refuses missing Partner credentials, GA4 configuration, locales, or unknown states.

6. Refresh and verify

Use Fetch data on Overview. A completed configuration shows Awaiting first data until Shopify has delivered the first GA4 event; only then does it become Connected. Confirm the app appears in the selector, lifecycle events arrive, annual charges are divided by twelve for MRR, Traffic gets GA4 data, and the sync health stays green.

dokku logs mantle -t
curl -fsS https://mantle.newcraft.dev/healthz

7. Rotate credentials

Create the replacement secret, update the same Dokku ENV key, restart the app, verify sync, and only then revoke the old secret. Rollback means restoring the prior ENV value; database metadata does not need to change.
